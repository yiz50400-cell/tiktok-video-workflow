# 去水印备用步骤：本地试验与接入建议

建议自建工作流控制部分，调用成熟修补引擎。干净原片优先；失败后才生成水印遮罩和修补候选。员工继续在 Codex 下达请求、查看前后对比，无需另建工作台。

## 方案比较

| 方案 | 自建部分 | 效果与限制 | 本轮状态 |
|---|---|---|---|
| OpenCV Telea | 遮罩、位置切换、视频重组 | 快速空间插值，人物细节处容易涂抹；用于基线比较 | 本地样片实测 |
| LaMa 本地引擎 | 模型适配、逐帧遮罩、编码、结果检查 | 单帧重建通常比插值自然，但不是视频时序模型，可能闪烁或重建错误 | 6 秒 LaMa 样片已获用户接受；选为默认备用引擎 |
| 真正视频时序引擎 | 相同任务接口，增加 GPU worker | 能利用相邻帧，但计算、模型条款和复杂内容效果均需验证 | 未部署 |
| 商业修补 API | 上传/提交、回执、超时重试、费用上限、结果验证 | 员工无需安装 GPU 环境，但增加处理费用与上传时间 | 未选供应商、未配置凭据、未调用 |

不训练自有基础模型。先保留稳定的引擎接口；在真实样片中比较后选择默认引擎，避免员工工作流依赖某个擦除网站的 GUI。

## 工作流接口

输入：源素材 ID、失败原因、时间区间、逐帧遮罩或人工校准区域、保护区域（人脸/商品/文字/关键动作）、质量档位、费用上限、引擎。

输出：衍生素材、遮罩预览、处理前后对比、引擎版本、耗时、失败原因、质量审查状态。保留源文件与来源记录。自动修补输出先进入 NEEDS_VISUAL_REVIEW，不自动作为可发布素材。

流程：

1. 尝试干净源；取得后核对同视频身份与画面。
2. 获取失败且有水印原片时，定位水印在全片的移动、淡入淡出和镜头切换。
3. 标记水印与人物、包装文字、色号和动作的交叠，生成遮罩预览。
4. 引擎生成候选；超时或失败保留原件并返回原因。
5. 检查残留、边缘、拖影、闪烁、人物与商品失真、声音和时长；展示前后对比。
6. 人工接受后才转为剪辑可用素材；失败时换引擎、镜头或重新制作。

多人使用时，由共享后台排队分配 worker。Codex 是客户端；模型装在 worker 上，员工无需每人安装一套。第一阶段使用本机 worker 验证效果；多人账号、队列和 GPU 部署仍属于后续阶段。

## 本轮试验范围

在 `experiments/watermark-fallback/` 实施可丢弃原型。输入仅为已经下载的带水印 Eli 视频；修补阶段不读取此前拿到的干净播放版本。用样例校准区域与多帧固定白色字形估计遮罩，根据帧内水印匹配得分切换左右位置，分别调用 OpenCV Telea 与 LaMa，再重组音视频。

LaMa 由 IOPaint 官方适配文件引用的模型发布地址取得，校验与适配文件提供的 MD5 一致。运算使用 M1 CPU。逐帧断言修补前编码阶段遮罩外像素完全不变，原文件哈希不变。

本原型不能泛化识别任意水印，区域需要校准。遮罩位置跟踪不等于时序修补；两种引擎均为单帧方法。调用成功和视频可解码不等于视觉质量合格。首次试验发现彩色 logo 不在白字遮罩内，已追加图标遮罩；人物耳朵处的错误重建属于质量风险。

## 实测结果与当前结论

第二次试验处理原片 3–9 秒，576×1024、30fps、180 帧，包含水印从左侧切换至右侧。耗时：Telea 推理合计约 0.91 秒，LaMa 约 112.30 秒，整轮约 122.22 秒（本机 M1 CPU；不代表其他素材、分辨率或 GPU 性能）。

抽查第 0、60、120、179 帧：目标平台字样和图标在这些帧中已被修补；Telea 在耳朵附近出现明显涂抹，LaMa 更自然但重建的耳朵细节仍不准确，背景也有局部修补痕迹。原有色号文字保留。这不是精确恢复原始像素，也不是全片质量通过。用户随后明确接受 LaMa 的自然度，当前 6 秒 LaMa 样片记为 `ACCEPTED_BY_USER`，可作剪辑候选。此验收不包含 Telea，也不扩展至整条原片或未来任意视频；后续修补仍展示对比。

`projects/sheglam-color-bloom/watermark-fallback-trial-v2/comparison.mp4` 从左至右为带水印原片、Telea、LaMa。三份输出均执行完整音视频解码检查，原文件 SHA-256 保持不变。对比视频只是本轮实验的展示；生产队列、通用遮罩检测、MCP 修补工具和商业 API 均未接入。

下一步建议把修补封装为可替换适配器，再接 Codex 的“生成候选 → 展示对比 → 接受或退回”流程。多个员工共用队列与 worker；本地 CPU 引擎可保留为备用，批量生产的 GPU 时序引擎或商业 API 必须另用真实样片测效果、时延和费用后选定。

## 核实的来源

- [LaMa 官方项目](https://github.com/advimman/lama)：图像修补，仓库许可证 Apache-2.0。
- [IOPaint 官方项目](https://github.com/Sanster/IOPaint)：README 说明支持 CPU、GPU 和 Apple Silicon，自托管；仓库许可证 Apache-2.0。具体服务版本与维护状态需在正式部署前复核。
- [IOPaint LaMa 适配](https://github.com/Sanster/IOPaint/blob/main/iopaint/model/lama.py)：公开模型地址、MD5、推理接口。
- [ProPainter 官方项目](https://github.com/sczhou/ProPainter)：视频修补，官方部署要求 CUDA；S-Lab 许可证规定非商业使用，商业用途需联系贡献者，不能直接作为公司默认引擎。

原始阅读快照保留于 `docs/research/2026-10-09/watermark/`。没有调用外部商业去水印服务，也没有上传样片或产生 API 费用。模型下载与安装仅用于此本地试验，未改员工全局环境。

## 已确认的选择与费用

LaMa 作为默认备用修补引擎；先找干净源，找不到再修补。当前采用本地运行，没有按视频、分钟或 API 调用收费，也未上传收费服务。成本来自本机算力、耗电与处理时间；后续若迁移云 GPU，另计算机器费用。Codex 负责调度和审查，本地 LaMa 负责修补像素。6 秒样片验收已记录，批量服务仍待接入。
