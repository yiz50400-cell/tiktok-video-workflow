# 第一步：Codex 视频工作流的可操作预览

用户已确认 Codex 为员工平台、采集到发布为完整目标，并授权分步实现，每步看效果后调整。此步是本地验收版本，不代表团队生产部署完成。

## 交付与边界

1. 可运行的轻量面板：新建真实任务、查看持久化任务、商品/市场/数量/预算/来源、导入视频、在线播放原素材、流程节点、活动记录。
2. 真实 API：任务创建与查询、素材流式上传、媒体时长/尺寸/编码读取、文件哈希去重、取消任务。只推进已实现的节点。
3. 可运行 stdio MCP：Codex 可创建/查询任务、查询能力、从员工明确提供的本地路径上传文件。此步输出配置样例，不改用户全局配置。
4. 完整流程图显示采集、分析、镜头规划、中文审核、本地化、配音、剪辑、成片审核、发布。已接通本地导入；平台自动采集、创作、配音、渲染、发布显示待接通。
5. 独立只读流程预览使用明确标注的示例，不能登记为真实任务、声称已渲染/发布或计入实际统计。

## 架构

React/TypeScript 轻量面板 → FastAPI → SQLAlchemy 存储/媒体服务。为本机即开即用，预览用项目 `.runtime` 下 SQLite；多人部署前迁移到 Postgres、员工认证、队列与素材预约。此步不开放局域网，不声称具备团队并发/角色审批能力。业务接口保持可迁移。

MCP 通过 HTTP 调用相同 API；媒体字节走上传接口，不进模型上下文。源文件不改动，文件与任务数据留在项目 `.runtime`，测试使用临时目录。服务器仅监听 127.0.0.1，检查 Host/Origin，并使用本机会话凭据；凭据不提交或返回到日志。

## 验收

浏览器真实创建任务 → 上传一段测试视频 → 预览与元数据可读取 → 重复上传不会生成重复素材 → 刷新/重新建应用后任务仍存在。无素材不会报告已分析；未实现的渲染/发布不能推进。MCP stdio 初始化与工具调用可创建/查询真实任务。前端构建和后端测试通过。

## 后续可见检查点

第二步接来源采集、真实素材分析与镜头预览；第三步接 Codex 文案/独立审计与两个确认节点；第四步配音、剪辑、字幕与真实样片；第五步团队身份/共享素材与队列；第六步目标平台发布、定时任务和发布结果。每一步独立展示并收集反馈，发布账户凭据到对应步骤再配置。
