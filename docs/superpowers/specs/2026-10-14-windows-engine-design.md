# Windows 引擎与中转接入设计

## 已批准范围

先完成制作引擎跨平台适配和现有中转联调，为 Windows 自定义 Codex 界面及 EXE 提供可调用入口。本阶段交付源码、启动入口、诊断和验收记录。Mac 验证不能计为 Windows 实机验收。

## 合同

- 数量沿用每任务指定的 1–100 整数和现有质量门禁；不改历史批准或音色证据。
- 文件锁覆盖任务、修补、制作目录和音色批次；竞争时保持原有阻止重复执行语义。
- 原子文件发布前关闭临时文件句柄，异常不得破坏已成功记录。
- Windows 媒体子进程先进入 Job Object，再启动业务进程；超时和调用者异常终止整个进程树。POSIX 保留独立进程组。
- 文件和子进程文本使用 UTF-8；路径含空格及中文可执行。
- 新渲染默认 libx264；显式历史编码器保留。字体必须绑定具体文件哈希，历史 Mac 字体缺失时明确报错，不替换已确认包装。
- 启动依赖使用 Windows 路径和本机/发行目录查找；源码启动与内置环境安装包分别记录。
- 只读取选中的中转 provider，保留模型 gpt-6-sol。Key 不进入日志、报告、命令行或发行包；隔离配置通过 env_key 接入，不修改个人配置。
- Codex 联调限少量请求，验证真正的 Codex 调用和一次本地工具调用；不据此推定现有桌面插件全部可继承。
- 发布权限、付费服务、素材授权按现有规则处理。

## 验证

真实跨进程锁竞争/异常释放、子进程超时、关闭句柄再发布、UTF-8 往返、中转配置隔离与脱敏测试；真实 FFmpeg 在中文空格目录编码/解码；完整回归。Windows 专属测试在 Windows 11 上执行后才能通过平台门禁。后续 EXE 需干净 Windows 安装、更新和卸载验收。
