# 07 发布接入开发

## 目标和最新用户决定

> **当前决定（2026-10-13）：暂停整个第07步。工作流不接发布。成片交付后，员工自行在紫鸟/TikTok中手动上传、挂商品和发布。本文件以下开发目标仅保留作历史记录，不能作为当前执行授权。**

员工入口是 Codex。用户自己运营已有商品橱窗的账号，覆盖墨西哥、巴西、印尼、菲律宾。当前不做任何发布接入；成片、字幕、中文说明和交付包完成后，由员工自行手动上传、挂商品和发布。

本会话接续公开接口与竞品调研，开发本地准备及可替换送达入口；按阶段展示真实结果。真实账号尚未指定，未获上传、应用授权或正式发布授权；不要擅自操作。不要把离线模拟当平台验证，也不把收件箱或上传成功写成草稿已保存。

## 第一步

把“真正平台草稿”“TikTok App 收件箱待编辑”“本地发布准备包”分别说明，给出简洁推荐和待核验项。利用已有官方文档继续核实普通 Upload API 的准入及原生草稿入口，不重复全量竞品搜索。然后先开发本地发布准备入口，复用实际成片，输出可查看的中文发布预览、准确目标语言标题及标签、封面选择、商品待选说明和结构化记录。

重要：发布标题或包装如超出已确认中文原意、增加新卖点，按 AGENTS.md 用中文确认；不新增外语全文人工审批。未知商品 ID 不猜，不将同名跨市场商品混用。

## 建议文件归属

本会话可新增 workflow/publishing/、scripts/prepare_publish.py、tests/test_publishing*.py、docs/modules/publishing.md，以及 projects/sheglam-color-bloom/publishing-dev/ 的阶段产物。必要测试使用临时目录。

共享核心 workflow/api.py、cli.py、store.py、mcp_server.py、media.py、主依赖及 .runtime 业务库由主会话接入；先提交接口建议，不改动共享核心或其他模块。无需工作树；本目录非 Git。沿用各员工本机执行，不搭网页工作台、中央服务或共享队列。

## 后续可见验收

- 第一阶段：本地准备包及中文预览，清楚说明尚未上传。
- 第二阶段：取得具体目标账号、市场、商品及相应上传授权后，单条实际送达验证。若需要授予应用访问权限，交由用户按该步骤授权。
- 第三阶段：核实平台草稿或收件箱的真实记录，员工手动挂商品并发布；获相应授权后记录可核实的内容 ID、链接和挂载结果。

不要为了缺少账号而空转或无限调研：先交付本地可做部分，再提出最小账号信息问题。没有原生草稿能力时解释并给出最接近的可用入口；用户决定是否接受。优先减少操作步骤，不增加额外审批仪式。

## 接入选择依据

TikTok Shop Post Shoppable Video 官方接口真实存在，支持 product_id；China 注册地区示例查询 BR/MX 有卖家自用开发者类别，ID/PH 暂无。具体公司地区、应用和账号未实测。用户允许手动挂商品后，此接口留作后续候选。

TikTok 通用 Upload API 是 App 收件箱待编辑送达，不是可后台管理的草稿箱；Direct Post 对纯内部团队上传工具有用途审核限制。不能混淆这三条路线，不能承诺所有市场通用。

浏览器路线若采用紫鸟，使用 ziniao-webdriver-doc 及相关 reference；紫鸟只管理环境，TikTok 业务入口另验。不要关闭用户浏览器、改代理或读取无关账号凭据。本轮不接收费服务、不登录无关项目、不上传现有样片到外部。
