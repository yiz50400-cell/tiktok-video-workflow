## 已实现

- **改稿影响判断**：用稳定的句子 asset_key 比较版本，列出新增、删除、改写、需重录和可复用句。相同文字但音色/语速等 voice_settings 改变，也要求重录。移动句子重算位置依赖；修改后旧字幕时间、画面对齐复核和导出标记失效。
- **版本绑定**：逐句核对实际 WAV 文件哈希、精确文本的 UTF-8 哈希和原生导入 ID；计划声明 voice_settings 时清单也须绑定该配置。每次运行先重新读取录音，再决定是否复用准备结果。
- **真实活动与空档**：按各声道检测 PCM16 活动，反相立体声不混为静音。检查片头、句内、句间、片尾停顿，以及录音末端仍有活动、声音超出画面窗口、整段无活动。技术活动检测不等于语音识别或听感判断。
- **按任务判断停顿**：四类阈值由本片方案显式提供。刻意展示动作的停顿可保存原因、审核人及当前 gap_id；录音、文字、时间线或阈值变化，旧审核失效。自然呼吸与有意义的动作停留仍按本片需要处理。
- **字幕数据检查**：核对当前原生卡片的文字完整性、删除句残留、顺序、场景边界、活动起止偏差及有声但缺字幕区间。文字仅忽略空白/换行与 Unicode 规范化差别；显示可读性和逐词听审仍要实际复核。
- **时长建议**：根据已复核的动作最短时长、可用画面最长时长及起止留白，生成旁白驱动的方案。只提出有保护余量的外部静音裁切，不删词、不变速、不自动压掉句内停顿。固定总时长冲突会明确报错，不擅自补空白。
- **失败隔离**：失败证据进入输出目录 rejected/，不覆盖先前成功结果。新输入使用新版本目录；相同版本验证哈希后复用。

## 内部入口与格式

沿用 --plan、--assets、--tracks、--output；增加以下参数：

| 参数 | 用途 |
| --- | --- |
| --recordings recordings.json | 当前最终 PCM16 WAV 清单和真实导入绑定 |
| --pause-policy pause-policy.json | 本片四类间隔阈值及精确停顿审核 |
| --previous-plan previous-plan.json | 改稿对比；必须同时提供以上两项 |
| --caption-cards native-cards.json | 可选，当前原生字幕卡片及边界偏差阈值 |
| --picture-bounds picture-bounds.json | 可选，仅生成重排建议，不修改实际批次 |
| --fixed-duration-frames N | 配合 picture-bounds 检查固定时长冲突 |

录音清单是列表，每项包含 asset_key、path（绝对路径）、sha256、text_sha256、asset_id；计划声明 voice_settings 时增加一致配置。文本哈希来自对应录音生成记录/实际核实，不能只改哈希替旧音频贴新稿标签；哈希只验证声明绑定，不证明录音确实读了这些词。

停顿策略包含 max_gap_seconds（opening、within、between、ending 四个非负有限数值）及 allowed_pauses 列表。停顿审核项含 gap_id、reason、reviewed_by；ID 从本版实测报告获取。阈值由当前片子决定，不是统一风格。

字幕输入包含 max_offset_seconds 及 cards 列表；卡片含 asset_key、text、全片秒数 start_seconds / end_seconds。ChatCut 原生微秒时间先除以 1,000,000，核对来源是最终旁白轨。图像约束按每句 asset_key 映射 min_picture_frames、max_picture_frames、lead_frames、tail_frames，须来自真实镜头和完整动作检查。

--recordings 和 --pause-policy 必须成对。旧调用仍兼容，但明确标为未执行录音空档检查。整段 --voice 切分先单独完成；最终分句音频导入后，再运行受检入口，避免检查一种录音却提交另一种录音。跨目录调用使用项目 Python 与脚本的绝对路径。

## 执行顺序与输出

1. 新稿使用新版本目录；不变句保留稳定键，新增句分配新键，删除句从当前计划去除。保存准确批准范围与音色参数。
2. revision_impact 列出重录项；沿用句级缓存，仅生成变化句。相同句仍校验文件、文字和配置。
3. 需要时用 propose_narration_schedule 获取建议。审核画面对应、完整动作及实质时长变化后，重新准备最终音频和镜头计划，再运行入口。
4. 生成 narration-audit.json，以及可选 revision-impact.json、narration-schedule.proposal.json、caption-sync-audit.json。原预览仍为 validateOnly:true。
5. 使用隔离的新版本时间线或核实原生替换范围；不要向旧成片直接追加 adds。删除句不能残留旧配音/字幕。工具只提供依赖与预览，不会自己删除编辑器素材。
6. 用最终旁白生成/修正原生字幕，再查询卡片检查。未输入卡片时明确标为未检查，不能称字幕轨已更新。
7. 原生验证、提交、完整动作/声音/字幕复核和导出后技术检查按原流程执行。技术通过不授予中文稿批准、音色听审或成片验收。
