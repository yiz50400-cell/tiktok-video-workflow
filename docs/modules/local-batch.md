# 本地批次恢复入口

员工仍在 Codex 中发起任务；这个入口只是把已经批准的单条制作目录串起来，不是新的工作台，也不执行发布。

依赖首次准备后，日常调用复用本地环境，避免每次等待依赖服务重试。以下是已真实跑通的目录，可安全复用；新制作使用新的编号目录。

```sh
uv run --offline --no-project \
  --with-requirements requirements.lock.txt \
  --with-requirements requirements-production.txt \
  python scripts/run_local_batch.py \
  <已批准的单条制作目录>
```

开发机实测目录为 `projects/sheglam-color-bloom/batch-run-dev/2026-10-10-br-03/efficiency-v0001/production-benchmark-v0002`（本机证据，未随仓库）。

首次安装或依赖升级时省略 `--offline`；缓存不完整时不能使用离线模式。该选项只控制依赖解析，配音仍需联网。已有历史成片但没有对应成功阶段记录的目录不会被自动接管或覆盖。

入口按顺序执行三个阶段：准备配音与包装证据、渲染成片、技术 QA。开始前检查 `zh-approval.json` 是否绑定当前 `creative.json`，以及当地语言审核是否绑定同一个批准版本；审批证据不完整时会在网络配音和渲染前停止。

每个阶段写入同目录的 `stage-state.json`。成功阶段会校验输出文件哈希并复用；失败阶段下次只重试该阶段；输入版本变化必须使用新的编号目录。阶段日志分别写入 `stage-prepare.log`、`stage-render.log` 和 `stage-qa.log`，总结果写入 `batch-run-result.json`。

逐句配音最多并发 3 条；出现 429、服务端错误或连接超时，先收拢已提交请求，再退避并串行重试失败句子，每句最多 3 次。单次生成总等待上限 60 秒，成功句子按文案、音色、参数及文件哈希缓存；持续失败时明确停止并保留缓存。兼容服务地址已真实验证，但第三方可用性和限流不能保证。

准备入口支持单源/多源、批准方案中的实际时长和审核过的包装文字。`approved-template.json` 可重放现有已批准方案：必须绑定当前中文批准、当地语言审核、锁定音色、镜头布局及原始素材证据；继承镜头和包装，重新生成缺失配音。它用于同方案验证，不计为新创意。

`--stage prepare` 可单独准备，无需已有成片；`--stage render` 和 `--stage qa` 分别恢复后续阶段。技术检查成功与实际试听、完整播放、用户最终验收分别记录。

LaMa 修补命令默认 `--device auto`：Apple 芯片优先 MPS，CUDA 优先于 MPS，其他环境回退 CPU。设备会进入任务指纹，不能把 CPU 结果误当成 MPS 结果。06 的同一 17.4 秒片段实测 CPU 673.89 秒、MPS 296.25 秒；MPS 结果仍须画面复核，不能仅凭解码通过自动批准。

2026-10-12 实测：已有批准素材和包装、配音缓存 0/5 命中，准备 6.696 秒、渲染 6.349 秒、技术 QA 4.632 秒，阶段间总耗时 17.740 秒。同任务离线依赖启动加复用命令约 0.24 秒；复用不是新生产速度。详细证据见 [06 效率验证](../06-efficiency-validation-2026-10-12.md)。

2026-10-14：新制作目录支持已确认的 `creative.production` 配置，按实际句数、镜头、尺寸、包装及市场音色池准备。主任务 [完整链路](pipeline.md) 串联采集、可选修补、分析、创作/确认、内部本地化、音色分配、此单条入口及本机交付。新源片须保存内部切点和连续动作复核，短于2秒的实际镜头逐项说明。历史样例保持原恢复路径。真实新商品批量产能以实际执行和逐条质量验收记录为准。
