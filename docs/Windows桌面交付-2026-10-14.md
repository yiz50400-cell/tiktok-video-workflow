- Electron 官方 SHA256、Codex npm SHA512 完整性与 Windows wheel 锁中 SHA256 均校验。运行资源 manifest 记录 5,170 个文件；安装资源内容及最终 UI/main/preload 与源码逐一匹配。
- 真实 stdio 中转测试：保留读取时配置的 `gpt-6.1-sol`；短回复 12.367 秒、本地读文件 15.530 秒，后者有实际成功工具记录。没有修改用户原 Codex 配置或替换其模型。
- 本机真实 Electron 窗口已打开，观察到已配置连接和连接握手就绪；真实 Windows sandbox setup、Windows safeStorage 与完整 Windows 客户端任务执行仍待实机。

## 分发与运行范围

老板可把测试 ZIP 发给指定 Windows 试用人员。每位员工安装后设置自己的中转、模型、Key 及工作目录，准备 Windows 本地执行环境并执行诊断。任务数量按本次输入，单任务 1–100；需要更多可拆成多个任务。

当前各员工本机独立执行。共享素材跨机器预约、公司中央任务协调没有实现。搜索、浏览器操作、ASR 与 OCR 以实际工具接入为准；本壳不能自动继承现有 Codex Desktop 的全部插件。给定链接下载工具已内置，但 TikTok 来源可用性、真实素材和观察证据仍需核验。

LaMa 模型和 GPU 修补环境不纳入基础安装，需要独立部署验收；没有偷偷把修补能力标成已通过。更新为退出程序后覆盖安装，新版由人工分发，无自动更新服务器。卸载配置保留 app data；真实恢复行为仍按验收清单验证。

技术交付计数不能代替逐条听感、动作完整、文字遮挡与最终成片认可。当前短模型请求耗时和测试回归时间都不能证明批量视频产能，速度与稳定性需按用户实际指定的数量压测。

npm audit 记录 8 个 moderate 构建依赖警报，根因 sprintf-js 的无界精度 DoS；当前 registry 最新同为 1.1.3，没有可直接升级的修复。安装 app.asar 只打包桌面运行所需依赖与桥接代码，构建链不作为员工业务入口。未使用 audit force 建议降级构建器。

## 可重复构建

先安装 package-lock 中的开发依赖，使用开发 Python 与 uv 获取发行资源；不读取员工 Key：

```sh
python scripts/download_release.py https://registry.npmjs.org/@openai/codex/-/codex-0.152.0-win32-x64.tgz .runtime/windows-downloads/codex-0.152.0-win32-x64.tgz
python scripts/download_release.py https://github.com/electron/electron/releases/download/v44.7.2/electron-v44.7.2-win32-x64.zip .runtime/windows-downloads/electron-v44.7.2-win32-x64.zip
python scripts/download_windows_wheels.py distribution/windows-runtime.lock.txt .runtime/windows-downloads/wheels
python scripts/stage_windows_runtime.py
npm run desktop:ui
npm run desktop:test
npm run desktop:win
```

保持 release locks 和下载 pins；文件变更后重新校验资源 manifest、安装包 SHA、凭据扫描和回归。构建成功后继续执行 `distribution/Windows实机验收清单.md`；不要把上述构建流程当作实机验收。
